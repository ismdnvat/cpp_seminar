Компиляция

Перевод C++ в ассемблер: текст, где каждая строка — одна простая команда процессора. Здесь работает оптимизатор.

Ассемблирование

Перевод ассемблера в байты машинного кода, почти один в один. Результат — объектный файл .o. В нём ещё нет адресов чужих функций.

Ассемблер

Из чего состоит ассемблер

square.cpp
int square(int x) {
    return x * x;
}
$ g++ -S square.cpp $ less square.s
square.s, строки с точкой (.cfi…, .LFB0) убраны
_Z6squarei:                # метка: здесь начинается square(int)
    endbr64                # отметка «сюда можно прыгать», пропускаем
    pushq   %rbp           # сохранить старый rbp на стек
    movq    %rsp, %rbp     # rbp = вершина стека
    movl    %edi, -4(%rbp) # положить x (он пришёл в edi) в память
    movl    -4(%rbp), %eax # eax = x
    imull   %eax, %eax     # eax = eax * eax
    popq    %rbp           # вернуть старый rbp
    ret                    # выйти, ответ лежит в eax

Строки, которые начинаются с точки, — служебные пометки для ассемблера. Их можно не читать: из 40 строк файла кода здесь 9.

Строка ассемблера — одна команда процессора

  • метка _Z6squarei: — имя места в коде. Так компилятор записал square(int)
  • инструкция movl, imull, ret — что сделать
  • операнды — с чем: регистр, число или память
чтосмысл
%rax, %rdi, %rsp…регистры: 16 ячеек по 8 байт прямо в процессоре. %eax — младшие 4 байта %rax
%edi, %esiсюда кладут 1-й и 2-й аргумент функции
%eaxотсюда забирают результат
$5знак доллара — просто число 5
-4(%rbp)ячейка памяти по адресу rbp − 4
movl a, bb = a: откуда слева, куда справа
…l, …qбуква в конце — размер: l — 4 байта (int), q — 8 байт
add / imul / cmpсложить, умножить, сравнить
jmp / jl / call / retперейти, перейти если меньше, вызвать функцию, вернуться

Вопрос залу

Почему int делится на 2 длиннее, чем unsigned?

int div2(int x) {
    return x / 2;
}

unsigned udiv2(unsigned x) {
    return x / 2;
}
g++ -O2 -S div2.cpp (clang -O2 — так же)
_Z4div2i:
    movl    %edi, %eax
    shrl    $31, %eax   # взять знаковый бит: 1, если x < 0
    addl    %edi, %eax  # прибавить его к x
    sarl    %eax        # сдвинуть вправо на 1
    ret
_Z5udiv2j:
    movl    %edi, %eax
    shrl    %eax        # просто сдвинуть вправо на 1
    ret
Зачем три лишние инструкции для int?

Сдвиг вправо делит на 2, но округляет вниз: −7 >> 1 = −4. А C++ округляет к нулю: −7 / 2 = −3.

Поэтому для отрицательных x компилятор сначала прибавляет 1: (−7 + 1) >> 1 = −3. У unsigned отрицательных нет — хватает одного сдвига.

nm

nm: кто что просит и кто что даёт

шаг 1. собрать объектные файлы, без линковки
$ g++ -c main.cpp -o main.o $ g++ -c geometry.cpp -o geometry.o
шаг 2. посмотреть, какие имена в каждом
$ nm main.o 0000000000000000 T main U _Z4areaii $ nm geometry.o 0000000000000000 T _Z4areaii
шаг 3. то же с -C: имена в виде C++
$ nm -C main.o 0000000000000000 T main U area(int, int) $ nm -C geometry.o 0000000000000000 T area(int, int)
буквасмысл
Tесть: тело функции лежит в этом файле (T — text, так называется секция с кодом)
Uнужно: файл вызывает функцию, но её здесь нет (U — undefined). Адреса нет, поэтому слева пусто
D, B, Rглобальные переменные и константы. Маленькая буква — имя видно только внутри файла

Как искать ошибку линковки

  • undefined reference to X: в каком-то .o есть U X, а T X нет ни в одном из переданных файлов
  • multiple definition of X: T X сразу в двух файлах
  • линковщик просто ставит каждой U в пару T с тем же именем
Линковщик

Кто ругается: компилятор или линковщик?

ситуациякто и что скажет
вызвали area(3, 4), а объявления нет нигде
компилятор: 'area' was not declared in this scope
объявление в .h есть, geometry.cpp не передали в g++
линковщик: undefined reference to `area(int, int)'
объявили area(int, int), а определили area(double, double)
линковщик: undefined reference. Для него это разные имена: _Z4areaii и _Z4areadd
тело функции в .h, заголовок подключён в два .cpp
линковщик: multiple definition of `area(int, int)'
сделали #include "geometry.cpp" в main.cpp и собрали оба файла
линковщик: multiple definition — тело попало в оба .o

Правило: в .h — объявления, в .cpp — определения, #include — только заголовков.

Си-строки

Строка в Си — массив char с нулём в конце

char s[] = "hello";          // 6 байт: 5 букв + '\0'
const char* p = "hello";

std::printf("%zu\n", sizeof(s));        // 6
std::printf("%zu\n", std::strlen(s));   // 5
'h''e''l''l''o''\0'

Нуль-терминированная строка

  • длина нигде не хранится — её находят, дойдя до '\0'
  • функция получает только адрес первой буквы и идёт до нуля
  • нет '\0' — функции уйдут читать чужую память

Свой my_atoi

int my_atoi(const char* s) {
    while (*s == ' ') {
        ++s;
    }
    int sign = 1;
    if (*s == '-' || *s == '+') {
        sign = (*s == '-') ? -1 : 1;
        ++s;
    }
    int result = 0;
    while (*s >= '0' && *s <= '9') {
        result = result * 10 + (*s - '0');
        ++s;
    }
    return sign * result;
}

Почему перекрытие ломает копирование

Копирование слева направо в a + 1 затирает ещё не скопированное:

aaaaaf

aaaaaf вместо aabcdf. memmove в этом случае копирует справа налево.

Когда что

  • сдвиг внутри одного массива — memmove
  • длина известна — memcpy, неизвестна — strcpy

Массив массивов, массив указателей, указатель на массив

Как читать объявления

От имени вправо, пока можно, потом влево. Скобки меняют порядок.

  • int* cells[3]: массив из 3 элементов типа int*
  • int (*row)[4]: указатель на массив из 4 int
  • int m[3][4]: массив из 3 элементов типа int[4]

    for (int i = 0; i < rows; ++i) {
        for (int j = 0; j < 4; ++j) {
            std::printf("%d ", m[i][j]);

        std::printf("\n");

}

В памяти они разные

  • int m[5][4] — 20 чисел подряд, указателей внутри нет
  • int** ожидает, что в памяти лежат адреса строк
  • чтобы найти m[i][j], нужна длина строки, поэтому 4 обязательна в типе
argv

Аргументы командной строки

#include <cstdio>

int main(int argc, char* argv[]) {
    std::printf("argc = %d\n", argc);
    for (int i = 0; i < argc; ++i) {
        std::printf("argv[%d] = \"%s\"\n", i, argv[i]);
    }
}
$ ./args hello "big world" 42 argc = 4 argv[0] = "./args" argv[1] = "hello" argv[2] = "big world" argv[3] = "42"

Что приходит в main

  • argc — сколько аргументов, включая имя программы
  • argv — массив Си-строк; char* argv[] ≡ char** argv
  • argv[argc] всегда nullptr
  • числа приходят строками: "42"
